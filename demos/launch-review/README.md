# 轻舟商城：上线前的注意力队列演示

目标：观众不需要理解代码，只需看懂三个 Agent 同时工作时，人如何依次做决定。界面与对话使用简体中文；Mac 运行 TopCard，工作区显示为 `ubuntuvm`，实际 SSH 别名为 `ubuntu-vm`。

## 故事

轻舟商城准备上线。三个会话分别检查优惠券、库存和发布配置。它们不是三个互不相关的问题，而是同一次发布的三条工作线。

| 卡片标题 | 首轮工作 | 交给人的信息 | 人的下一步 |
| --- | --- | --- | --- |
| 优惠券 · 等你定规则 | 检查满减券的最低实付金额 | 订单可能变成负数，需确认是否允许零元订单 | 回复「最低实付 1 元，按这个规则修复并补测试。」 |
| 库存 · 验收通过 | 验证库存不足与正常扣减 | 检查通过，可以收尾 | 标记已处理 |
| 发布 · 检查中 | 检查生产环境配置 | 调试模式已关闭，但尚缺上线签字 | 暂不实际发布，只生成检查清单 |

## 必须拍到的队列优势

1. 优惠券卡片位于前台，库存卡片在后台完成后排到队尾。当前阅读位置保持不变。
2. 人暂时不决定优惠券规则，点击下沉，先处理库存结果。
3. 将库存标记已处理后，回到优惠券卡片。输入一句中文决策并发送，卡片进入 Working，下一张自然接上。
4. 尾帧停在「一个会话继续工作、一个结果等待处理」的画面，让读者看到队列不是关闭任务，而是分配人的注意力。

## 约 15 秒分镜

| 成片时间 | 画面 | 字幕 |
| --- | --- | --- |
| 0–3 秒 | 优惠券在前台，两个会话在 Working | 多个会话并行，一次只看一张 |
| 3–6 秒 | 库存完成，进入队尾；前台不变 | 后台完成，不打断当前思路 |
| 6–9 秒 | 下沉优惠券，审阅并处理库存 | 先处理能决定的 |
| 9–13 秒 | 输入优惠券规则并发送，卡片进入 Working | 一句决策，让任务继续 |
| 13–15 秒 | 下一张卡片接上，画面停留 | Just handle the top card. |

不要均匀加速整段录像。剪掉模型等待时间，保留卡片转场、点击与结果各 0.5–1 秒；中文输入可以加速，但发送前保留完整句子至少 1 秒。

## 真实运行与重放边界

真实执行应在单独的演示目录进行，三个会话各用独立目录，避免并行修改同一个文件。所有任务只运行本地测试，不部署、不调用生产接口。

若用固定结果重放，必须在演示说明中标明「基于真实执行结果的交互重放」，保留原始执行日志与对应结果；不可将预设的完成时机描述为实时 Harness 探针验证。若全程实录，则记录原视频，发布时说明剪辑与加速。
